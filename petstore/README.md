# ЗооМаркет — CRM для продавцов

Учебная платформа для отработки навыков тестирования.
Тестирование проводилось в рамках выполнения тестового задания.

**Ссылка на стенд:** https://petstore-frontend-sbtg.onrender.com/

## Задача

Провести функциональное и исследовательское тестирование CRM-системы
для продавцов зоотоваров. Проверить основные пользовательские сценарии,
работу REST API и корректность отображения данных на UI.

## Что было сделано

**Ручное тестирование**
- Составлен чек-лист на 30+ проверок.
- Проведено функциональное, интеграционное и регрессионное тестирование.
- Найдено 7 дефектов, из них 2 критических.

**API-тестирование**
- Коллекция запросов в Postman.
- Автотесты на Pytest + Requests для CRUD-операций с питомцами.
- Негативные сценарии: доступ без токена, невалидные данные.

**UI-тестирование**
- Автотесты на Playwright: логин, таблица питомцев, доступ без авторизации.

**SQL-аналитика**
- Аналитический запрос: топ-10 продавцов по самой продаваемой категории
  за последние 2 месяца.

**Безопасность**
- Обнаружена уязвимость IDOR: доступ к чужим заказам через API.
- Написан PoC-скрипт в режиме dry-run (только чтение, без изменений).

## Найденные дефекты (кратко)

| Дефект | Приоритет |
|--------|-----------|
| IDOR: доступ к чужим заказам через `GET /api/orders/{id}` | Critical |
| Удаление проданного питомца через `DELETE /api/pets/{id}` | Critical |
| `GET /api/dashboard` возвращает 500 | Critical |
| `POST /api/pets` принимает отрицательную цену | High |
| 500-е ошибки под нагрузкой (50 итераций) | High |
| Документация: отсутствует статус `placed` | Low |

## Выводы

Основные проблемы — в контроле доступа и валидации входных данных.
